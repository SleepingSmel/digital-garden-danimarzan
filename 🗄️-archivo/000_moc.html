⚡ GUÍA DE SINCRONIZACIÓN

Regla de oro: Siempre haz PULL antes de empezar a editar, y PUSH antes de cerrar.

Flujo correcto desde Obsidian (PC)

Al empezar a trabajar:

  1. Abrir Obsidian
  2. Ctrl+Shift+P (Pull — traer cambios de GitHub)
  3. Esperar a que sincronice
  4. Trabajar en las notas

Al terminar de trabajar:

  1. Ctrl+Shift+S (Sincronizar — commit + push)
  2. Esperar a que sincronice
  3. Cerrar Obsidian

Al cambiar de dispositivo:

  1. En el dispositivo anterior: Ctrl+Shift+S (push)
  2. En el nuevo dispositivo: Ctrl+Shift+P (pull)
  3. Trabajar
  4. Repetir al cambiar de nuevo

Flujo correcto desde Telegram (Zor)

Cuando pides algo a Zor por Telegram:

  1. Zor trabaja en el VPS
  2. Zor hace commit y push a GitHub automáticamente
  3. Tú haces Ctrl+Shift+P en Obsidian para traer los cambios

Si Zor te dice que algo se subió a GitHub, siempre haz pull en Obsidian antes de editar ese archivo.

Cómo evitar conflictos

  1. SIEMPRE hacer pull antes de empezar a editar
  2. SIEMPRE hacer push antes de cerrar Obsidian
  3. NO editar el mismo archivo en dos dispositivos a la vez
  4. NO forzar el cierre de Obsidian mientras sincroniza
  5. Si Zor está trabajando, espera a que termine antes de editar

Si hay un conflicto (como el de hoy)

Si Obsidian te dice que hay un conflicto:

  1. Cerrar Obsidian completamente
  2. En terminal (en la carpeta del vault):
  1. Volver a abrir Obsidian

¿Qué significa --theirs? Significa “quedarse con la versión de GitHub” (la más reciente). Casi siempre es la correcta.

Resumen visual

OBSIDIAN (PC) ←——pull——→ GITHUB ←——push——→ VPS (ZOR)
     ↑                                              |
     └──────────── Ctrl+Shift+S ────────────────────┘
  • Ctrl+Shift+P = Pull (traer de GitHub a Obsidian)
  • Ctrl+Shift+S = Push (subir de Obsidian a GitHub)
  • Zor por Telegram = Trabaja en VPS → push a GitHub → tú haces pull

2. PLUGIN DE GIT EN OBSIDIAN

Instalación (PC)

  1. Abrir Obsidian → Configuración → Plugins de la comunidad
  2. Buscar “Obsidian Git” (por Vinzent03)
  3. Instalar y activar
  4. Ir a Configuración del plugin Obsidian Git

Configuración del plugin

En Configuración → Obsidian Git:

✅ Auto backup interval (minutes): 5
✅ Auto pull on startup: Activado
✅ Auto push on activado: Activado
✅ Pull updates on activado: Activado
✅ Commit message: "vault backup: {{date}}"
✅ Subfolder: (vacío, todo el vault)

Conectar con GitHub (primera vez)

  1. Crear repositorio en GitHub (privado o público)
  2. En terminal (en la carpeta del vault):
  1. En Obsidian Git plugin, configurar:
    • SSH Key: Generar una clave SSH y añadirla a GitHub
    • Passphrase: La que hayas puesto a tu clave SSH

Uso diario del plugin

  • Ctrl+Shift+S → Sincronizar (pull + commit + push)
  • Ctrl+Shift+P → Pull (traer cambios de GitHub)
  • Ctrl+Shift+U → Push (subir cambios a GitHub)

3. SINCRONIZACIÓN PC ↔ MÓVIL ↔ NUBE

Opción A: GitHub (Recomendada)

PC:

  1. Plugin Obsidian Git configurado (como arriba)
  2. Sincronizar antes de cerrar y al abrir

Móvil (Android):

  1. Instalar Termux desde F-Droid
  2. En Termux:
  1. Abrir Obsidian → Crear vault → Seleccionar la carpeta clonada
  2. Para sincronizar: abrir Termux y ejecutar:

Móvil (iOS):

  1. Usar la app Working Copy (cliente Git para iOS)
  2. Clonar el repositorio
  3. Configurar Working Copy como carpeta de Obsidian
  4. Sincronizar desde Working Copy antes y después de editar

Opción B: Obsidian Sync (de pago)

  1. Comprar Obsidian Sync ($4/mes)
  2. Activar en Configuración → Sync
  3. Crear vault remoto
  4. En móvil: Conectar al mismo vault remoto
  5. Sincronización automática

Opción C: Syncthing (gratis, sin nube)

  1. Instalar Syncthing en PC y móvil
  2. Compartir la carpeta del vault entre dispositivos
  3. Sincronización P2P (sin pasar por la nube)
  4. No usar con Git al mismo tiempo (puede causar conflictos)

4. CÓMO EVITAR QUE GIT SE CORROMPA

El problema común

El archivo .git/index se corrompe cuando:

  • Se cierran dos instancias de Git al mismo tiempo
  • Se fuerza el cierre de Obsidian mientras sincroniza
  • Hay conflictos de merge no resueltos
  • El disco se llena durante una operación Git

Solución cuando Git se corrompe

Paso 1: Cerrar Obsidian completamente

Paso 2: En terminal (en la carpeta del vault):

Paso 3: Si hay conflictos de merge:

Paso 4: Si nada funciona (nuclear option):

Prevención (lo más importante)

  1. SIEMPRE hacer pull antes de empezar a editar
  2. SIEMPRE hacer push antes de cerrar Obsidian
  3. NO editar el mismo archivo en dos dispositivos a la vez
  4. NO forzar el cierre de Obsidian mientras sincroniza
  5. Si ves un error de Git, NO ignores — resuélvelo inmediatamente

Configuración anti-corrupción en Obsidian Git

En la configuración del plugin:

✅ Pull updates on startup: SÍ (siempre traer cambios al abrir)
✅ Auto backup interval: 5 minutos
✅ Push on backup: SÍ
✅ Disable push: NO
✅ Show status bar: SÍ (para ver el estado de sincronización)

5. COMUNICACIÓN CON ZOR DESDE TELEGRAM

Cómo funciona

Zor está conectado a Telegram. Puedes enviarle mensajes desde la app de Telegram y Zor responderá. Zor tiene acceso a:

  • El vault de Obsidian (en el VPS)
  • Internet (búsqueda, scraping, APIs)
  • Herramientas de investigación (Firecrawl, TranscriptAPI, etc.)
  • GitHub (para subir/bajar cambios)

Formato de mensajes para Zor

Para pedir una transcripción:

Transcribe el video de Jett Franzen: [URL]

Para pedir investigación:

Investiga sobre [tema]. Busca datos, citas de expertos, conexiones con filósofos.

Para pedir citas:

Dame citas potentes sobre [tema] de autores reconocidos.

Para pedir que organice el vault:

Organiza la carpeta [X]. Mueve archivos, crea enlaces, añade tags.

Para pedir que suba a GitHub:

Sincroniza el vault con GitHub.

Para pedir un guion:

Desarrolla una idea para guion sobre [tema]. Usa las transcripciones de Jett y las citas de la biblioteca.

statusMuestra el estado del vault y Git
backupHace un backup completo del vault
search [tema]Busca en todo el vault
new [tipo] [título]Crea una nueva nota

6. INSTRUCCIONES PARA TAREAS ESPECÍFICAS

Cómo crear una nueva transcripción

  1. Daniel envía URL del video de Jett a Zor
  2. Zor extrae el transcript con TranscriptAPI
  3. Zor crea el archivo en Transcripciones/ con el formato:
    • Header (título, autor, fecha, URL, vistas)
    • Transcripción literal (inglés)
    • Traducción al español (literal)
    • Conexiones con autores (mínimo 6, enriquecidas)
    • Notas de traducción
  4. Zor actualiza _REGISTRO.md
  5. Zor sincroniza con GitHub

Cómo crear un nuevo guion

  1. Daniel envía la idea (audio o texto) a Zor
  2. Zor crea la nota en Transcripciones/
  3. Zor busca conexiones con transcripciones de Jett
  4. Zor busca citas de autores que refuercen los puntos
  5. Zor desarrolla la estructura del guion (hook, desarrollo, cierre)
  6. Zor sincroniza con GitHub

Cómo investigar un tema

  1. Daniel pide investigación sobre un tema
  2. Zor busca en internet (Firecrawl, Exa, etc.)
  3. Zor busca conexiones con autores/filósofos
  4. Zor crea nota en Research/
  5. Zor enlaza con guiones y transcripciones relacionadas
  6. Zor sincroniza con GitHub
