🧠 FILOSOFÍA DE GUIONES — Dani Marzán

Creado: 2026-05-29 Propósito: Definir la filosofía de creación de guiones para que el sistema (Zor + NotebookLM + Claude Cowork) opere correctamente Basado en: Análisis de “Demuestra tu Carácter” + investigación de Víctor Heras, Jordi Segués, Fer Miralles, Isra Bravo, Alex Hormozi

📌 PRIMERA PRINCIPAL: EL FRAMEWORK NO ESCRIBE. EL FRAMEWORK REVISA.

Daniel ya tiene resultados probados. Millones de views. Comunidad real. Su instinto de guionista está calibrado por la experiencia.

El error sería: Usar Claude Opus para generar guiones desde cero siguiendo un template. Lo correcto es: Daniel escribe → El sistema revisa, conecta, mejora.

🔄 FLUJO ÓPTIMO DE CREACIÓN

1. DANIEL tiene una idea / experiencia / reflexión
         ↓
2. DANIEL escribe el guión (en su voz, con sus palabras, sin pensar en estructura)
         ↓
3. SISTEMA revisa con checklist (NO reescribe, solo señala)
         ↓
4. DANIEL decide qué aplicar
         ↓
5. SISTEMA conecta con autores, añade citas, datos, referencias
         ↓
6. DANIEL graba

✅ CHECKLIST DE REVISIÓN (no de escritura)

Esto es lo que el sistema revisa DESPUÉS de que Daniel escribe. No antes.

Apertura

  • ¿Los primeros 3 segundos tienen un gancho fuerte? (afirmación, pregunta, imagen visual)
  • ¿Apela a la IDENTIDAD del espectador, no a su intelecto?
  • ¿No hay introducción? (sin “Hoy voy a hablar de…”)

Desarrollo

  • ¿Hay dolor visual? (el espectador se ve reflejado)
  • ¿Hay una historia personal? (1 por guión mínimo)
  • ¿Anticipa objeciones? (si el espectador pensaría “sí pero…”, el guión lo resuelve antes)
  • ¿Hay variedad tonal? (no es monótono todo el rato)

Cierre

  • ¿Hay cierre circular? (vuelve a la frase/imagen del inicio)
  • ¿Hay CTA? (llamada a la acción: comenta, suscríbete, reflexiona)
  • ¿La última frase es memorable? (algo que se quede grabado)

Conexión con autores

  • ¿Se puede conectar con algún autor/filósofo? (para dar profundidad)
  • ¿Hay alguna cita que potencie el mensaje?

Viralidad (Víctor Heras)

  • ¿Pasa el Filtro 550? (¿lo entiende un niño de 5 años? ¿le interesa a 50 de cada 100 personas?)
  • ¿Está en uno de los 4 pilares? (salud, dinero, sexo/relaciones, desarrollo personal)
  • ¿Hay algún elemento contracorriente? (ir contra la creencia popular)

🎯 LO QUE DANIEL YA HACE BIEN (y no hay que tocar)

  1. Vulnerabilidad real. “Yo siempre dejé que me pisotearan.” Eso no se fabrica.
  2. Transición nicho → universal. Lo hace sin que se note.
  3. Metáforas propias. Película de miedo, porteros, la vida como partido.
  4. Tono conversacional. No suena a conferencia.
  5. Frases de marca. “He fracasado. Y me alegra.” “Te callas la puta boca y entrenas.”
  6. Polarización natural. Dice cosas que incomodan sin forzar.

🔧 LO QUE EL SISTEMA PUEDE MEJORAR (sin tocar la esencia)

  1. Cierre circular. Añadir una frase que conecte con el inicio.
  2. CTA explícita. “Comenta X”, “Dime qué piensas”, etc.
  3. Frecuencia de ganchos. Mini-gancho cada 60-90s (pregunta retórica, dato, cambio de tono).
  4. Conexión con autores. Inyectar citas de Epicteto, Camus, etc. que potencien el mensaje.
  5. Datos/estadísticas. Si aplica, añadir un dato concreto que respalde el argumento.
  6. Micro-historias. Asegurar que hay al menos 1 historia personal por guión.

🚫 LO QUE NUNCA HACER

  1. Reescribir el guión de Daniel. El sistema sugiere, Daniel decide.
  2. Forzar un framework. Si el guión funciona sin seguir la estructura, no tocarlo.
  3. Hacer guiones desde cero con IA. Daniel es el autor. Siempre.
  4. Añadir relleno. Si algo no aporta, sobra. Aunque el framework diga que “debe estar ahí”.
  5. Perder la voz de Daniel. El sistema no escribe. Conecta, revisa, mejora.

📚 STORYTELLING: PRINCIPIOS CLAVE (no reglas)

Estos son los principios que Daniel ya aplica de forma natural. El sistema los usa como lente de revisión, no como plantilla.

1. El espectador quiere saber qué pasa después

  • Cada frase debe llevar a la siguiente
  • Preguntas abiertas o retóricas generan curiosidad
  • No reveles todo al principio. Dosifica.

2. El dolor es el gancho. La esperanza es el cierre.

  • Empieza con el problema (dolor visual)
  • Cierra con la solución (esperanza, desafío)
  • El espectador se queda porque quiere llegar a la solución

3. Lo concreto vence a lo abstracto

  • “Portero temblando de miedo” > “Falta de confianza”
  • “Me hablaban con mala forma y yo bajaba la cabeza” > “Baja autoestima”
  • Siempre: imagen > concepto

4. La historia personal es la prueba

  • “Yo siempre dejé que me pisotearan” = credibilidad
  • Sin historia personal = conferencia
  • Con historia personal = conexión

5. El cambio es el arco

  • Antes (yo me dejaba pisar) → Después (ya no lo permito)
  • El espectador quiere saber: ¿cómo pasó? ¿qué cambió?
  • Si no hay cambio, no hay historia

6. La repetición crea énfasis

  • Repetir la frase clave 3 veces (cada vez más alto/intenso)
  • No es redundancia. Es hipnosis.

7. Las pausas son parte del guión

  • 2 segundos de silencio después de una frase clave
  • El silencio genera tensión
  • La tensión genera atención

🤖 CÓMO USA LAS 3 HERRAMIENTAS

ZOR (Hermes Agent en Telegram)

  • Función: Revisión de guiones + conexión con autores + análisis de retención
  • Cuándo: Después de que Daniel escribe un guión
  • Output: Checklist de revisión + sugerencias + conexiones con autores

NOTEBOOKLM

  • Función: Razonamiento profundo sobre el guión
  • Cuándo: Para guiones especiales o cuando Daniel quiere profundizar
  • Fuentes: DANIEL.md, MARCA.md, GUÍA-CONTENIDO.md, autores filosóficos, análisis de Víctor Heras
  • Preguntas tipo:
    • “¿Qué le falta a este guión para conectar con la audiencia de 18-35 años?”
    • “¿Qué diría Jordi Segués de este gancho?”
    • “¿Cómo mejorar el cierre usando storytelling de Fer Miralles?”

CLAUDE COWORK

  • Función: Análisis técnico del guión (estructura, ritmo, retención)
  • Cuándo: Para revisión detallada de guiones largos
  • Output: Análisis timestamp por timestamp + sugerencias de mejora

🎬 EL SISTEMA NO ES ITERATIVO. ES AUTOMATIZADO.

El objetivo NO es: Daniel escribe → Zor revisa → Daniel corrige → Zor revisa → Daniel corrige…

El objetivo ES: Daniel escribe → Sistema revisa en SEGUNDO PLANO → Daniel recibe un documento con sugerencias → Daniel graba (aplicando lo que quiera)

Una sola iteración. Sin fricción.

El sistema aprende de cada guión que Daniel escribe. Con el tiempo, las sugerencias serán más precisas porque el sistema conocerá mejor la voz de Daniel.

Documento vivo. Se actualiza con cada guión analizado. Última actualización: 2026-05-29
